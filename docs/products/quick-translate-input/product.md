# Quick Translate Input

## 概要

Macで入力中の行を、末尾に選んだ合図を入力することで翻訳して元の入力欄に戻すツール。
文章を書くアプリから離れずに、別の言語で文章を書くために使う。

## 背景と解決する課題

### 背景

[AZU-369](https://linear.app/azu/issue/AZU-369/ctrlshiftaで入力内容を翻訳するツールを作る)を起点に、入力中のテキストを翻訳して置き換えるツールを作る。
利用者との確認により、翻訳の合図は文字の入力、Ctrl＋Shift＋Aは行選択の補助操作とする。

### 解決する課題

文章を書く途中で翻訳ツールへ移動し、原文と訳文をコピーして戻す手間を減らす。
翻訳のために入力中の文章や作業場所を見失わず、書き続けられるようにする。

## ターゲットエンドユーザー

### Macで別の言語の文章を書く利用者

- **特性:** Macの入力欄で文章を書き、キーボードで操作する。
- **抱える課題:** 入力中の文章を翻訳するために、別のアプリへ移動している。
- **利用文脈:** アプリを限定せず、入力欄で文章を書き、送信・保存する前に翻訳する。

## 提供価値

### 入力している場所で翻訳できる

- **対象:** Macで別の言語の文章を書く利用者。
- **内容:** 翻訳の取得と入力欄への反映を、一つの操作から行える。
- **提供理由:** 翻訳に必要な手作業を減らし、文章を書く流れを保つため。

## 成功の定義

利用者が普段のアプリで文章を書き、翻訳ツールへの移動や手動のコピーをせずに翻訳を反映して、作業を続けられる。
対象以外の文章を壊さず、処理を完了できない場合にも元の入力を保てる。

## プロダクト開発を進める上での指針

翻訳エンジンにはAppleのTranslation frameworkを使う。これは利用者の指定による。
言語モデルの準備が必要な場合があるため、初回の準備と日常の操作を区別する。
言語モデルの準備については、[Appleの公式サンプル](https://developer.apple.com/documentation/translation/translating-text-within-your-app)を参照する。

対応アプリを増やすために、意図しない入力欄や文章を書き換える処理を追加しない。
不確かな状態では入力を保ち、利用者がやり直せることを優先する。
訳文は下書きとして扱い、送信や投稿は利用者が行う。

## SLA・SLI・SLO

### SLA

サービス水準の保証は設けない。
個人利用のMac向けツールとして作り始め、外部サービスとして提供する契約は扱わないため。

### SLI・SLO

数値目標は未設定。
まず対象アプリと操作を決めて受け入れ条件を確認し、処理時間と置換の成功率を実測してから必要性を判断する。
未計測の速度や対応率を実績として扱わない。
